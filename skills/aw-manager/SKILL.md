# aw-manager

Read at runtime; if it can't load, report and stop. Read-only with respect to code: route each card/PR to whoever can decide; never review or fix.

## Rules
1. **Never decide whether work is complete** (the agent resumed via `invoke_kanban_agent`, or a human, does). Exceptions: Not needed archiving, Priority check, SweepBlock third rule, ChildCards guard.
2. **Non-terminal run on the card (running/pending) = untouchable.** Skip.
3. Non-empty `child_cards` = epic: never resume/dispatch (ChildCards guard).
4. Every no-progress touch ends in a named routing action; a comment alone is not enough.
5. Never merge a PR, never remove `devteam:awaiting-fixes` yourself (only a coder, see stale labels), no GitHub write yourself: your `gh` is UNAUTHENTICATED: read-only log fetch is best-effort, no routing decision may depend on it (use gate data). PR writes only via an authorized Coder.
6. **Resolve the Plan iteration FIRST, by tool call, never from prompt text alone:** `get_run(<your own run id>)`; a parent run with `initiator_kind=plan_cadence` = in an iteration (`initiator_id` = id). The prompt's `Plan iteration id:` line is only the fallback if `get_run` errors or shows no parent. Outside an iteration never call `get_plan_memory`/`update_plan_memory`.
7. **Every gate candidate gets an action AND a why**, no-touch included (`skipped`, `backed-off`, `deferred`, `human-routed`): write them in ONE batch call, `annotate_plan_iteration_card(slug, iteration_id, items=[{card, action, why, disposition}, ...])`, before `finish_plan_iteration` (no candidates: skip the call). Report every skip/deferral with its reason.
8. **Unblock first, Q&A search is a MUST.** Always try to unblock a card before routing it to a human, and on every (re)evaluation of a card. Before ANY `ask_human`, `need_human` move or "a human is needed" report, and before re-evaluating a blocker, search the curated Q&A registry: `qa_search(query=<the blocker, in the words of the card>)` (tags such as `human-not-needed`, `do-it-yourself`, `unblocking`), plus `knowledge_search` (`aw__aw_knowledgeable__*`). A hit that gives a way to act (CDP instead of TCC grants, server-side trace instead of waiting for a reply) means the card goes to the agent that can do it, with the Q&A id and answer as evidence; it is never Need Human. Record the queries and hits in the `🧹` comment and the report; "no hit" is stated, never skipped. If `qa_search` is absent (older Knowledgeable connector) or errors after one retry, use `knowledge_search` alone (it also returns Q&A hits); if that fails too, the card is `deferred` with reason `qa-unavailable` (free skip, no human routing, no park, no `ask_human`) and the report names it as a failure: a failed search is never a negative result and never satisfies this rule.

## Ending the turn
Every turn (wakeups too) needs a terminal action. **Card-less** (`NOTION_TASK_ID` empty): first check windows walked (budget spent, `next_offset` null, or 4 read), every candidate annotated (batch), Signal A run, plan memory written + `finish_plan_iteration` (a 409 lists the cards still missing action/why: annotate exactly those, retry once); then `mark_flow_done(outcome="success", qa_not_needed=true, summary=<report>)` (`"partial"` only for a named tool failure). **Card-bearing: NEVER call `mark_flow_done`** (it moves the card); use `return_to_caller_agent(kind="result")` or a handoff. **Detached** (no caller, run started with `call_me_back=false`/no callback): `register_callback` each dispatched run, then end with the report; never `mark_flow_done`.

## Input
**A:** `selector: stale-sweep` | `github-maintenance` | `stale-sweep-v2` (read `/opt/aw-workspace/skills/aw-manager/stale-sweep-v2.md` and follow it; dry run by default); unknown: report and stop. **B:** work orders, card-shaped (`page_id`, `reason`, `evidence`, advisory `suggested_action`; `get_kanban_card` for EVERY card first, the ChildCards guard overrides `suggested_action`) or PR-shaped (`pr`, `url`, `reason`, `evidence`; see PR writes); neither: report and skip.
Per card: back-off, ChildCards guard, run check, matrix, touch (`🧹 manager:` comment naming the action, stamp).
**Touch budget: Fixed 10 per invocation, any mode** (stale-sweep: Batch 1 takes `7 - priority`, 3 reserved, Batch 2 takes `10 - priority - batch1`). A touch changes a card or starts work (`invoke_kanban_agent`, `run_agent_async`, `move_kanban_task`, `ask_human`, archive); skips and already human-routed cards are free (max 30 walked non-touch, rest `deferred`).
Candidates: `list_kanban_cards_need_attention(limit=25)`, top-down; budget unspent and `next_offset` set: next window (max 4).

## Priority check (first; cap 5)
- **Signal B:** `qa_status == need_human` AND `status == "In Progress"` (no back-off): move to `need_human` with `🧹` comment AND a named routing action.
- **Signal A:** latest run `flow_needs_human=true`, Status never reached Need Human. `list_flow_needs_human_cards()` returns one row per card (`latest_flagged_run`, `latest_run`, `total_cards`, `truncated`); `truncated=true` or a tool error is a NAMED FAILURE (`signal-a-truncated`): report it, never proceed as if Signal A were complete. Verify the latest UNFILTERED run (drop if non-terminal/superseded), skip Need Human/Done/Archived, confirm a pending human-only-allowlist decision before moving, else ordinary candidate. Back-off applies to Signal A only.

## Run check
① `list_runs(notion_task_id=page_id, limit=1)`: running/pending: SKIP; terminal: `ended_at` must be `> STALE_RUN_MINUTES = 30` min ago else skip; empty list = no run ever (valid, go to ②, never an error/skip); call error: skip, never qualify. ② `list_runs(..., category="work", limit=10)`: resume target = newest row whose `source_slug` does not start with `qa-`; none: Batch 1 skip + wall `no-work-run`; Batch 2 (already Need Human) NO wall: matrix 2 fresh Architect, or free skip if already human-routed. Cap 25 probes.
## Batch 1: stale In Progress
`invoke_kanban_agent(page_id, run_id=<qualifying run>, message=...)`: still In Progress though run ended <N> ago; re-establish real state; exactly one outcome: (1) COMPLETE AND VERIFIED: `mark_flow_done` (merged code never `qa_not_needed=true`; QA 409 = read existing run, never `qa_rerun`); (2) KNOWN REMAINING WORK: do it now; (3) OPEN QUESTION: answer from evidence; `ask_human`/`need_human` ONLY for a human-only-allowlist reason. Explainable failure: `run_agent_async(slug=<run.source_slug>, ..., call_me_back=false)`. Then `add_kanban_comment("🧹 manager: ...")` and `register_callback(run_id)` (skip only when the result says `call_me_back: true`); never stamp at dispatch.
**Binding gap** (run says it closed the card / `"notion_task_id": null`, card still In Progress): one retry resume only if `success` and verified (never replay `failed`/`partial`); if that fails, comment only: do NOT move the card to Need Human.
## Batch 2: Need Human complement
Run check ① on every candidate (12h `last_edited_time` filter only for `routed-human`/`escalated` cards). Order: Layer A UnblockProbe (TRUE overrides back-off; FALSE skips Layer B), back-off, ChildCards guard (an epic has no blocker of its own; a backed-off epic is skipped before reading children), Layer B (max 3 read-only calls on the latest comment's blocker; never "resolved" when unverifiable). Resolved: resume original agent with evidence, card stays Need Human, clear SweepBlock/UnblockProbe. Else matrix.

## Routing matrix (one named action per touch)
1. **➡️ Coder** (more implementation, pinned run `error`, QA bounced on implementation): `run_agent_async(slug=<work run source_slug>, input=<page_id + prior summary + unfinished + 3-outcome contract>, notion_task_id=page_id, call_me_back=false)`.
2. **🏛️ Architect** (design/approach). 3. **📋 PO** (scope/priority/mootness/conflicting asks): same dispatch, `slug="architect"`/`"product-owner"`.
4. **🙋 Need Human**, only for the human-only allowlist: irreversible action on real data/users, spend, credentials/access only Frederico holds, speaking to externals for him, explicit "waiting on Frederico"/QA approved awaiting his sign-off, a prior architect/PO run concluding a human is needed. "No agent owns this" goes to the Architect. `ask_human(question=<decision + evidence>)`, then `move_kanban_task(status="need_human", comment="🧹 manager: 🙋 ...")` (`QAStatus="In Progress"` hard-locked: ask + comment only), SweepBlock `routed-human|1|<iso>|<detail>`, `UnblockProbe` if mechanically checkable.
Ambiguous: resume original session via `invoke_kanban_agent`; only if refused, matrix (Batch 2: architect). 1-3 defer the stamp: after the `🧹` comment call `register_callback(run_id)` and keep `(page_id, run_id, status_at_touch)`; 4 stamps inline.

## ChildCards guard
After back-off, before any resume/dispatch: `get_kanban_card` each child (terminal = `Done`, `Self-closed`, `Archived`). Any non-terminal: comment "epic container - not resuming", stamp, no SweepBlock. All terminal and `len(child_cards) < 25`: move parent to done. `len(child_cards) >= 25` without `has_more == false` (Notion truncates at 25): withhold auto-completion, comment, report.

## Back-off, stamp, SweepBlock
`LastSweptAt` (Manager-only): unset or `>=48h` qualifies; `<48h` only if a non-Manager comment is strictly after it; fail open on unreadable data. Dispatched cards stamp (ISO-8601) on the wake-up: **binding-gap resume** is checked FIRST: never a `resume-ineffective` hit, keep SweepBlock, route remaining work; else `error` or `success` with no new reply: wall `resume-ineffective:<session8>`; run moved card to Need Human: Layer B + matrix (one recovery hop per card per iteration); `success` with reply: clean, clear SweepBlock. No-dispatch touches stamp inline.
SweepBlock `<wall_key>|<count>|<iso>|<detail>` (Manager-only); keys `qa-dedup-409`, `no-work-run`, `no-session`, `resume-transport`, `resume-ineffective:<session8>`. Same key: increment; else 1; clean touch/Status change: clear. At 3 the third rule replaces the planned action: `move_kanban_task(need_human)` naming wall/count, `ask_human`, write `<wall_key>|escalated|...`; platform-shaped walls also `create_kanban_task` (agent `debugger`). Read the count BEFORE routing: route or escalate, never both.
UnblockProbe `<kind>|<arg>|<set_iso>|<detail>`: `pr-merged`, `run-terminal`, `card-status`. Validate `<arg>` with an anchored regex, separate args never a shell string, malformed = absent. NEVER treat unevaluable as TRUE. Cap 10.
## Selector: github-maintenance
Gate JSON `{has_work, prs, failing_flows, counts}` is advisory; re-read live (`GET $AW_WORKSPACE_API_URL/api/apps/git/github/maintenance?limit=20`, `X-Api-Key: $AW_WORKSPACE_API_KEY` from `/opt/aw-workspace/.aw-workspace/.env`; snapshot only on error, say so). Budget 10: PRs, then failing flows.
**`aw-run:` reasons first** (`badge: null`): `needs_human_label`: `ask_human` only, never a coder (the `devteam:needs-human` PR label is retired under lifecycle v2: human-needed state lives on the Kanban card / `ask_human`; a v1-lifecycle caller's `code-review.yml` can still apply it as a genuine human hold, so only treat it as stray when the repo's workflow is v2). `escalate (woken 3x, head unchanged)`, `unresolvable`: fresh coder with a scoped work order or `ask_human`; never re-wake the same session. `stuck_active` (may be the gate's own expiry: run likely dead): fresh coder, never re-wake the old session. `awaiting_fixes` (reason names `devteam:awaiting-fixes`/`fix-cycle` + the aw-run id; NOT a human hold): opener idle or run dead = fresh coder on the PR's EXISTING branch with the PR's open findings as the work order (see Review-findings work orders under PR writes; never a new PR, never `ask_human`); opener still active = skip. `out_of_repo` (blocking findings tagged as belonging to another repo): fresh coder in the OWNING repo's worktree (name the finding's repo), PR there, and a coder note on this PR linking it; never wake the opener, never `ask_human`. `waiting_human` carries a reason and is the only genuine human hold: `ask_human`, never a coder. `idle_open` (aw-run verdict, or an untagged Dev Team PR whose `attention_reason` has `idle_open:` at the start of ANY `;`-delimited reason, e.g. `badge:needs-review; idle_open: ...`): an open PR nobody has touched for >10min and no run is acting on it, whatever blocks it (round-1 review findings, a dead run, no `devteam:awaiting-fixes` label yet); wake a fresh coder with only the short order "load the aw-code-review-response skill and act on PR <url>"; never `ask_human`, never skip because the PR is already `devteam:reviewed`. If `out_of_repo` findings carry a `file` that is in the PR's own diff they are NOT out of repo: treat as `awaiting_fixes`. `recent|waiting_ci|active (stale labels on green PR: ...)`, or an untagged PR whose `attention_reason` has "stale labels on green PR" (not badge (d)): coder confirms green CI + `CLEAN`, clears/retriggers the stale labels (PR writes), then `/aw-review` or merge path per rules; `ask_human` only if the coder fails. `ask_unroutable`: `ask_human`. `aw_run.closed_dropped`: informational, no action. Fallback verdicts (`aw_run: {fallback: true}`): if `aw_run.labels` has a `devteam:needs-human` or is `null`, `ask_human`, never a coder. `ask_failed`/`ask_deferred`/`handed_off` not in `prs`, no pending question: `ask_human` once, never a coder.
**Per PR by badge:** (a) `tests-failed`: `run_agent_async(group_slug="coders", target_slug="github-maintenance-plan", ...)`. (b) `open` stalled/blocked (conflicts, review findings, red checks): same coder dispatch to unblock (rebase, fix MEDIUM+ findings, re-run checks) or close as stale, never merge. (c) `ready-to-merge`: known author (operator, `[bot]`, or the verdict's `author_association` OWNER/MEMBER/COLLABORATOR) gets a coder merge; `author_association` null or absent = unknown author: `ask_human`, no lookup; external PRs never auto-merged. (d) `needs-review`/other: `ask_human`; Never default to (a) on uncertainty.
**Failing flow (act, don't just file):** budget 5 dispatches per round. Per default-branch failing workflow: ① card via `create_kanban_task(finding_key="ci:<repo>:<workflow>", plan_slug="github-maintenance", target_slug="github-maintenance-plan", tags=["github","ci"])`; other terminal lanes: `move_kanban_task(status="backlog")` + re-detected comment (dedup reopens only from Done); `need_human`: report "already escalated". ② `list_runs(notion_task_id=page_id, limit=1)`: non-terminal = skip, no duplicate dispatch. ③ `gh run view <run_id> --repo <repo> --log-failed | tail -c 4000` (on error the coder fetches it). ④ `run_agent_async(slug="coder", target_slug="github-maintenance-plan", notion_task_id=page_id, call_me_back=true, input=<repo, workflow, run URL, excerpt, "diagnose the root cause, open a fix PR with `attach_pr_to_target`, never merge">)`. Escalate (`ask_human` then `need_human`, with the log excerpt and the coder run id) ONLY after a coder attempt on the card ended `error`/blocker/no PR, or a human-only input (credential, decision) is named; `occurrence_count >= 3` alone never escalates.
## PR writes
**Review-findings work orders (awaiting_fixes, out_of_repo, any coder acting on open findings):** the whole work order is "load the aw-code-review-response skill and act on PR <url>" plus the PR-specific facts (url, head sha, the current head's blocking set = MEDIUM+ plus any finding marked `blocks_merge: true` at any severity, why it is stuck). Never inline the rules (reply on every finding, push or merge, escalation): they live in that skill.
`suggested_action` is advisory. A write happens only when an authorized Coder (`run_agent_async(group_slug="coders", ...)`) performs it with its authenticated `gh`: nudge/rebase, explanatory comment, close with explanation, merge of a known-author `ready-to-merge` PR, qualified stray `devteam:needs-human` removal. Human hold, unknown/external author or `needs_human_label`: `ask_human`, no coder. Never touch gate-owned labels/statuses (`devteam:awaiting-fixes`, `devteam:review-capped`, `devteam/*`, `aw-run:*`) except a coder clearing/retriggering stale `devteam:awaiting-fixes`/`aw-run:*` after confirming green CI + `CLEAN`; unsupported action: skip, report. Work order carries url, action, evidence, end state and "recheck against the CURRENT head; if not authenticated or authorized or evidence is stale, make no write and report `no-auth`, `not-authorized` or `stale-evidence`"; skips are never success.
**Stray `devteam:needs-human` removal** (never apply or request the label; escalation is `ask_human`/the card; v1-lifecycle repos may still emit it as a real hold, leave those): only as resolver of its blocker (or explicit human instruction), and only if ALL hold on the current head: (1) label predates the latest commits, (2) CI green AND `mergeStateStatus` `CLEAN`, (3) at least one completed review of the current head exists AND EVERY completed review after the last push found nothing blocking (zero reviews never qualifies; one clean review beside a blocking one does not; a skipped or missing review does not count). Then in order: remove the label, comment the evidence, comment `/aw-review`. Never merge directly; never touch `devteam:awaiting-fixes`. Any failed condition: label stays, report why.
**Coders must run `attach_pr_to_target` after opening a PR**, or label/review events cannot wake them.

## Plan memory (only in a Plan iteration)
READ once before Batch 1: `get_plan_memory("kanban-sweep")` (supplements back-off, never overrides). Annotate every candidate via one batch call (action, one-line why, disposition; no budget: `deferred`, `pending`); annotations live on the iteration, not in memory. WRITE once before `finish_plan_iteration`: `update_plan_memory(slug="kanban-sweep", writer_key="kanban-sweeper", value=<whole subtree>)` keeping `carry` and a `schema_version: 2` entry (`iteration_id`, own `run_id`, `beyond_window`, `counts`; NO `items`), max 10; on 413 trim, retry once. Wake-ups write only per-card annotations (`expected_rev`), never a whole-subtree `value`.
## Not needed archiving
`move_kanban_task(status="archived", comment="🧹 manager: not needed - <evidence>")` ONLY for a retired repo (`agentic-workspace`) or work verifiably shipped elsewhere. Any doubt: normal path. Never use the board's literal "Not Needed" option.

## Report
Plain text: mode, candidates, windows/`scanned`, picks/skips with reasons, per-card action/outcome (`LastSweptAt` DEFERRED for dispatched cards), SweepBlock changes, PR/CI dispatches and skips; then end per "Ending the turn".
