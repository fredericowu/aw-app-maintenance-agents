# aw-manager selector: stale-sweep-v2

Loaded only when the input says `selector: stale-sweep-v2` (optional `dry_run: true|false`, DEFAULT `true`). The 6 hour cadence keeps running `stale-sweep` until a human repoints the plan; this file never changes that. Rules 2-6 and "Ending the turn" of SKILL.md still apply; where this file is stricter, this file wins.

## Dry run (`dry_run` true or absent)
ZERO writes and ZERO dispatches: no comment, no stamp (`LastSweptAt`), no SweepBlock, no `move_kanban_task`, no `run_agent_async`, no `invoke_kanban_agent`, no `ask_human`, no `create_kanban_task`, no plan memory. Read tools only. Print one table row per card: `card | blocker (as stated) | facts used | verdict | would-do | rule-or-judgment`. `rule` = decided only by the fixed rules below; `judgment` = the model read a comment. End with counts of rule vs judgment. A dry run is refused inside a Plan iteration: `get_run(<your own run id>)` shows `initiator_kind=plan_cadence` or a `plan_iteration_id` on YOUR OWN run (Manager launched directly as the Plan steward), or a `plan_cadence` parent. Refusal writes nothing to the board and dispatches nothing: no `annotate_plan_iteration_card`, no `update_plan_memory`, no card tool, and NO `finish_plan_iteration` (it closes the iteration and records a decision: a write, forbidden in a dry run). The refusal is report-only: end with the single line `dry run refused inside a Plan iteration` as your final text; closing the iteration is the Plan's business, never the dry run's (known platform limit: the Plan executor then records the open iteration as an error, so never point a Plan at a dry run; guard tracked on the card). Outside one, card-less ending: `mark_flow_done(success, qa_not_needed=true)` with the table as summary. Live (`dry_run: false`) only when the order says so explicitly.

## 0. Deploy check (every sweep, before the dossier; no LLM judgment)
Call `kanban_check_deployed(dry_run=<this sweep's dry_run>)` first: a dry run MUST pass `dry_run=true` (it then writes nothing), a live sweep passes `dry_run=false`. The tool itself moves a card only on a verdict transition, so repeating it is safe. Follow each verdict, one named action per card:
- `deployed` / `no_deploy_needed` + `QAStatus == done`: the tool already moved it to Done; nothing to do.
- `deployed` + not QA'd: the tool moved it to Testing and dispatched QA; nothing to do (409 = read the existing run, never retry).
- `rolled_back` (the tool leaves the card in place and only reports it): route to the coder that delivered it (`run_agent_async(slug=<work run source_slug>, notion_task_id=<card>, ...)` naming component, target version and observed version); never Need Human unless access is the blocker. Dedupe by the observed version, not by sweep: skip ONLY when a coder run for the card (any status, `list_runs(notion_task_id=<card>)`) already names this same observed version in its input; an unrelated coder run in flight does not block the handoff, so dispatch anyway. One dispatch per (card, observed version), never one per sweep.
- `invalid`: the tool already commented once (`already_reported`), so do NOT comment again; route to the delivering coder to fill `DeployComponent` / `DeployToVersion` (and `DeployEnv` / `DeployWorkspaces` when relevant; `none` only when nothing needs deploying), naming the row's `reasons`. `already_reported` only says the comment exists, not that a coder was dispatched: skip ONLY when it is true AND `list_runs(notion_task_id=<card>)` shows a coder run started after that comment; with no such run (a sweep that stopped before dispatching), route again.
- `pending` / `partial` / `unknown`: no action (the tool batches its own reminder; 3 unknowns escalate by itself). Report them.
Cards the tool moved are free skips for the stale dossier below. In the dry-run table add one row per deploy verdict (`rule`). Counts as touches only the invalid and rolled_back dispatches.

## Input: dossier, stale mode
Two calls, always `run_cost_analytics(filter_stale=true, facts_only=true, ...)` with the status filter explicit (the API default is both `running,need_human`): `statuses=in_progress, min_idle_hours=2` and `statuses=need_human, min_idle_hours=24`. `filter_stale_count=5` per call (page with `offset`; up to 20 with facts-only). The dossier excludes Manager runs from idle time and, with `honor_stamp` (default true), hides cards whose `card.last_swept_at` is newer than their latest run/`ask_human` fact. Live keys: `card.last_swept_at`, `card.sweep_block`, `card.unblock_probe`, `card.qa_status`, `card.finding_key`, `card.child_count`, `card.status`; `facts.open_pr`, `facts.all_prs_merged`, `facts.checks_failing`, `facts.merged_checks_failing`, `facts.unresolved_threads`, `facts.discovery_complete`, `facts.tag_gaps`, `facts.pr_heads[].head_sha`, `facts.any_run_in_flight`, `facts.hours_since_last_run`, `facts.last_pr_activity_at`, `facts.ask_human.{pending,answered}`. A key that is absent is UNKNOWN, never false. STAMP GATE: for every picked card, skip it when `card.last_swept_at` is newer than its latest fact (last run end, last human comment or `ask_human` answer, `facts.last_pr_activity_at`). If `card.last_swept_at` is missing from the card block, stay in dry run: a live sweep is refused (report `needs dossier v1.1`), because the old 48h and 30 minute back-offs do not apply to this selector. Dossier or GitHub unavailable (`facts.github_available` false): no verdict, no "gone", report and stop. The idle filter hides a card for 24h after an `ask_human` answer (the answer resets its idle clock), so add a THIRD call: `statuses=need_human, min_idle_hours=0, honor_stamp=false, filter_stale_count=-1`, and keep only cards with `facts.ask_human.answered` > 0 and `latest_answered_at` newer than `card.last_swept_at` (or unstamped): those are acted on even though `stale` is false.

## 1. Revalidate the blocker FIRST (every picked card, before any routing)
Apply the active-run and epic guards in rules 1 and 2 below first. For cards that pass both guards, follow rule 8 of SKILL.md (including its `qa-unavailable` deferral) before deciding how to route the blocker: run `qa_search` and `knowledge_search` on the stated blocker and list the queries and hits in the table's `facts used` column. Both searches are allowed in a dry run. A Q&A answer that makes the blocker actionable gives a `judgment` verdict "unblock by <agent>", never Need Human.
Fixed order, first match wins (`rule`); otherwise read the blocker comment and judge (`judgment`):
1. `any_run_in_flight`: SKIP (untouchable).
2. `card.child_count` > 0: epic, ChildCards guard of SKILL.md (`get_kanban_card` for `child_cards`).
3. CI card (checked BEFORE the generic PR rule; a CI card that also matches the PR rule is decided here only) (`finding_key` `ci:<repo>:<workflow>`; the key may name the old owner `tekflox`: resolve the repo under `fredericowu` first; for a private repo use only the dossier `ci` block, never unauthenticated `gh`): the stale list has no `ci` block and rejects `repo`/`workflow`, so first resolve `<workflow>` to a workflow filename or numeric ID (the key may carry a display name such as `Test`, which the workflow-runs endpoint rejects with 404: list the repo's workflows, match `name`, use its `path` basename or `id`; no match: treat as unknown), then call `run_cost_analytics(card_id=<card id>, repo=<repo>, workflow=<resolved filename or ID>, include_tool_stats=false)` and pass `ci_since=<the card's failure time>` and read its `ci` block, using `green_after_since` (never `gh`). GONE only if the latest default-branch run of that workflow is green AND newer than the card's failure. Older or unknown: not gone, and a Need Human card with a fresh human answer continues to rule 5 (the CI result never swallows the answer); otherwise still blocked.
3b. Manual-step guard (before rule 4): a Need Human card whose blocker comment or SweepBlock names a manual or human step (owner question, `ask_human` pending, real device or Mac check, credential, fixtures) and has NO answered `ask_human` or human comment newer than the parking (that case skips 3b and goes to rule 5) is NOT gone, even when every PR is merged and clean; rule 4 does not apply, route per sections 3 and 4 (a human-only wall stays parked). Rule 4 applies only when the stated blocker is the PR itself (failing checks, unresolved threads, unmerged PR). Discovery guard: `facts.open_pr` or `facts.pr_merged` null, or 0 PRs found for a card whose comments name a PR, means discovery is unreliable: stay in `judgment`, no `rule` verdict.
4. Not a CI card (rule 3 already took those): `facts.discovery_complete` true AND `facts.all_prs_merged` true AND `facts.merged_checks_failing` == 0 AND `facts.checks_failing` == 0 AND `facts.unresolved_threads` == 0 (the aggregate: merged-PR threads count; never `unresolved_threads_open` alone) (at least one PR): PR blocker GONE. Incomplete discovery or any other value: not gone.
5. Need Human card with an answered `ask_human` or a human comment newer than the parking: human answered, exit the card via the matrix.

## 2. Blocker gone
- CI card (rule 3): `move_kanban_task(status="done", comment="🧹 manager: default branch green since <run url/time>, newer than the failure")`. This is the ONE Done the Manager owns besides finished epics and the split.
- Delivery exists (merged PR): dispatch QA (merged work only; 409 = read the existing run, never retry, never `qa_rerun`; a passing QA run exists: `invoke_kanban_agent` so the card closes with that QA run id).
- Obsolete / no delivery: dispatch `product-owner`.

## 3. Still blocked: route by what unblocks it
Code or failing PR: coder. Testing: QA, MERGED work only. Clarification, scope, priority, accept/reject, obsolete or not: `product-owner`. Needs a deploy: coder. Design question: `architect`. One named action per touch, dispatch as in SKILL.md matrix 1-3.

## 4. Need Human guardrail
Before parking or keeping a card in Need Human, the Q&A search of SKILL.md rule 8 must have run on this blocker and found no way to act; cite it in the comment.
Need Human is for a wall no agent and no decision can remove. The Manager may move a card there itself only when the blocker is a hard show stopper: infrastructure down, missing access or credential, external outage. The comment must name the wall, the evidence, what was tried and the one human action that removes it. If any choice exists (scope, priority, trade-off, accept or reject, obsolete or not), the Manager does not park: it dispatches the PO and the PO decides, including whether to park. In doubt, it is a decision: call the PO. On its own show-stopper park the Manager also writes SweepBlock `routed-human|1|<iso>|<detail>` so reminders keep working; for a PO park it writes the same marker when the PO run calls back. A parked card returns to the sweep after 24h idle (Q3 expiry 1 day).

## 5. Partial QA: split
Only when a QA run on the MERGED revision verified the core criteria and the rest is unverifiable for access or infrastructure reasons. Order: (1) `create_kanban_task` the follow-up (own `finding_key`, parent = original, status Backlog); (2) confirm it is new: if the result has `skipped: true` or no new card id (archived dedup), STOP, do not close the original; (3) `move_kanban_task(done)` the original with a comment listing verified vs moved to the follow-up; (4) `ask_human` Frederico whether the follow-up is worth doing (holds nothing). Lean toward keeping the flow moving.

## 6. Loop guard
SweepBlock wall key per blocker, e.g. `pr-checks-failing:<repo>#<n>`; `detail` stores the PR `head_sha` at the last coder dispatch. Count = coder dispatches for that blocker (`list_runs(notion_task_id=...)`). At 2 with an unchanged `head_sha`, no new PR and unchanged card status: the next step is `product-owner`, never a third coder. A NEW blocker key resets the count to 1. Read the count BEFORE routing: route or escalate, never both.

## 7. Revalidation stamp and budgets
After each verification (live only) write `🧹 manager: Revalidated at <iso>: blocker <X> is still true because <evidence>` (or "gone because ...") AND set `LastSweptAt`. Stamps are free with their own cap of 15 per sweep. The Fixed-10 touch budget is reserved for dispatches and moves (touches); a stamp never spends it. Replaces the 48h and 30 minute back-offs for this selector.
